两类写入模式：
独占模式（Claude/Codex/Gemini）：切换 = 完全替换配置文件，只有一个"当前 provider"。
累加模式（OpenCode/OpenClaw/ZCode/Hermes/WorkBuddy/Kimi-Code）：多个 provider 共存，切换只是加一条/激活一条。

数据怎么流转

sequenceDiagram participant U as 用户 participant UI as 选择器
(首页/聊天页/Models页) participant API as switchProvider API participant ADP as TS Adapter participant F as Agent配置文件 participant DB as user.json U->>UI: 点一个模型 UI->>API: switch(agent, provider, model) API->>ADP: applyConfig ADP->>F: 写配置文件 (原子写) F-->>ADP: 成功 ADP-->>API: 完成 API->>DB: 更新 config.providers[agent] API->>DB: 自动追加 recentModels (置顶) Note over DB: recentModels 自动维护
用户无需手动操作 par 并行 API-->>UI: 切换成功 end UI->>U: 刷新显示
常用/最近置顶
关键：recentModels 是自动的 —— 用户每次切换成功，系统自动把这个模型加入"最近使用"并置顶。 favoriteModels 是手动的 —— 用户点 ⭐ 显式收藏。
所有模型选择器渲染时：置顶显示 favorite + recent，其余折叠到"显示全部"。

⑥ 实施顺序与依赖

⚠️ 不能跳序。如果先做目标②（首页）再做目标④（切换）， 首页的"常用模型点击切换"会触发有 bug 的切换路径，用户一点 Gemini 模型就丢 model， 反而比现在更糟。地基不稳，上层白搭。
